# IntelliAPI AI

**An Intelligent Agent for Real-Time API Threat Detection and Explainable Security Decisions**

> Educational prototype for a college AI mini-project. Demonstrates supervised machine learning, intelligent-agent decision making, HTTP/API security, and explainable AI.

---

## Overview

IntelliAPI AI analyzes incoming HTTP/API request representations with a trained machine-learning model, predicts whether each request is normal or an attack, estimates its risk, and selects an appropriate security action (ALLOW / MONITOR / BLOCK). Every decision is explained: which model features fired, which heuristics triggered, and why the agent chose its action.

A separate traffic simulator continuously generates realistic and attack-pattern requests every 4 seconds, sending them to the local inference API. A real-time React dashboard receives every analyzed event over WebSockets and displays it live with charts, statistics, and a per-request investigation panel.

---

## AI Concepts

| Concept | Implementation |
|---|---|
| **Intelligent reactive agent** | `backend/app/agent/policy.py` — Observe → Extract → Predict → Evaluate → Decide → Publish |
| **Supervised ML (Decision Tree)** | Interpretable baseline, `max_depth=12`, provides a DT decision path per request |
| **Supervised ML (Random Forest)** | Primary model, 150 trees, 96.4% accuracy on combined test set |
| **Feature engineering** | TF-IDF char n-grams (3-5) + 12 numeric features + OneHot method |
| **Explainability** | RF global feature importance, DT decision path, per-request model evidence |
| **Heuristic layer** | Separate regex-based SQLi/XSS/path-traversal/command-injection detection |

## Architecture

```
HTTP Traffic Simulator (port 5174)   ←→   Postman
               |
               | HTTP POST /analyze
               ▼
       FastAPI Validation  (port 8000)
               |
               ▼
  Feature Extraction + Preprocessing
  (same pipeline as training — no drift)
               |
               ▼
      Trained RandomForest Model
               |
               ▼
    Heuristic Layer (separate signal)
               |
               ▼
  Intelligent Agent Decision Policy
  (ALLOW / MONITOR / BLOCK + explanation)
               |
               ▼
    In-memory Event Store (+MongoDB Atlas)
               |
               ▼
   WebSocket Broadcast → Dashboard (port 5173)
```

Training is **offline** — run `python -m training.train` once, save artifacts, load them at service startup. The service never retrains on live traffic.

## Model Performance (actual, from held-out test set)

| Model | Accuracy | Precision | Recall | F1 | FPR |
|---|---|---|---|---|---|
| Decision Tree (baseline) | 84.05% | 0.9925 | 0.7540 | 0.8570 | 0.010 |
| **Random Forest (primary)** | **96.39%** | **0.9878** | **0.9549** | **0.9710** | **0.020** |

- CSIC-only subset accuracy: **96.24%**
- Synthetic-only subset accuracy: **96.82%**
- Confusion matrix (RF): TN=2395, FP=50, FN=191, TP=4040

### Dataset composition

| Source | Role | Rows |
|---|---|---|
| CSIC 2010 HTTP dataset (real) | Normal & Anomalous HTTP requests from e-commerce app | 60,851 |
| Labelled synthetic dataset | SQLi / XSS / path-traversal / command-injection requests | 9,000 |
| **Combined (after dedup)** | — | **33,379** |

Training: 80% | Test: 20% | Stratified split | Leakage-controlled (exact-duplicate signatures never span train/test boundary).

## Training the model (one-time setup)

```powershell
cd intelliapi-ai\backend

# Step 1: inspect the dataset
python -m training.inspect_dataset

# Step 2: train (takes ~3-4 minutes)
python -m training.train

# Step 3 (optional): verify artifacts reproduce training metrics
python -m training.evaluate
```

Artifacts written to `backend/artifacts/`:
- `pipeline_rf.joblib` — trained RandomForest pipeline (PRIMARY)
- `pipeline_dt.joblib` — trained DecisionTree pipeline (baseline)
- `metrics.json` — full evaluation metrics
- `feature_importance.json` — top 15 feature importances
- `training_config.json` — pipeline and threshold config

The CSIC 2010 CSV is read from `../../csic_database.csv~1/csic_database.csv` (two levels up from `backend/`). This default is set via `CSIC_CSV_PATH` in `.env`.

## Configuration

Copy `.env.example` to `backend/.env` and adjust as needed:

```dotenv
RISK_LOW_MAX=0.35          # p < 0.35  -> ALLOW
RISK_HIGH_MIN=0.70         # p >= 0.70 -> BLOCK
ENABLE_HEURISTICS=1        # 1 = heuristic layer on
MAX_EVENTS_STORED=2000     # in-memory ring buffer size
STORAGE_BACKEND=memory     # or "mongo" for MongoDB Atlas

# MongoDB Atlas (only when STORAGE_BACKEND=mongo)
MONGO_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/...
MONGO_DB=intelliapi_ai
```

## Demo workflow (college evaluation)

1. **Start the backend** (terminal 1). Confirm `model_loaded=True` in the startup log.
2. Open **Postman** → import the collection → run request 1 (Health) and 2 (Model Info). Show the 96.4% accuracy table.
3. Run requests 3–7 in Postman. Show normal vs attack responses, heuristic findings, and the decision tree path for each.
4. **Open the dashboard** at http://localhost:5173. Show the model evaluation confusion matrix and empty-state charts.
5. **Open the simulator** at http://localhost:5174 in a second tab.
6. In the simulator: configure the traffic mix, click **Start**. Show a new request every 4 seconds.
7. Switch back to the dashboard tab. Watch the stat cards, charts, and live feed update in real time.
8. Click a flagged row in the live feed. Walk through the **Threat Analysis panel**: ML prediction, attack probability, risk level, agent decision, model evidence, heuristic findings, and decision tree path.
9. Pause the simulator → Pause the dashboard display → Resume both.
10. Point out: all model metrics come from the held-out labelled test set. The live stats come from analyzed traffic. The two are clearly separated.

## Limitations and extensions

- The model is **binary** (NORMAL / ATTACK). Attack-type labels in the UI come from the heuristic layer, clearly labeled as such.
- The agent is **reactive** — it does not retrain online.
- In-memory storage resets on server restart. Set `STORAGE_BACKEND=mongo` and provide `MONGO_URI` for persistence.
- Per-request latency is ~130ms on a local machine (first call ~350ms due to JIT warmup). For a demo with 4s intervals this is fine.
- The heuristic regex patterns cover common textbook attacks. Novel obfuscated payloads may evade them while the model still catches them, or vice versa — this is an intended, honest demonstration of the two separate layers.
